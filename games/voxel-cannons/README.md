# 方块炮手 · CUBE SALVO

一款根据视频实际玩法独立制作的离线浏览器小游戏：四列彩色炮台、五个发射位置、逐层清空立体方块。

## 直接玩

解压后双击 `index.html`。无需安装依赖、启动服务或联网；需要支持并启用 WebGL 的现代浏览器；不支持时明确提示并暂停，不使用伪 3D 降级。浏览器是否允许本地文件保存进度取决于其设置；如保存不可用，游戏会提示。

## 操作

- 点击 3D 场景最前排的待命炮台，或下方四个颜色按钮，派入第一个空闲发射位。
- 炮台自动消除当前前方露出的同色方块，弹药用完后空出位置。
- 先看外层颜色，避免把五个位置全部留给暂时打不到的颜色。
- 清空雕塑过关。共十二关，通关后解锁下一关。
- 右上角菜单可暂停、继续、重开、选关、切换音效、轻动效和两种固定视角。
- 键盘 1–4 选择炮台；空格暂停/继续；Esc 菜单；R 请求重开。
- 进度自动保存在当前浏览器。重新打开有进行中的射击时会先暂停。

## 开发

- `src/levels.js`：十二关体素与弹药队列。
- `src/legacy-levels.js`：旧关卡定义，兼容已经进行中的旧版存档。
- `src/engine.js`：确定性射击与严格存档校验，无 DOM 或第三方依赖。
- `src/renderer.js`：Babylon.js 9.30.0 WebGL 引擎，实体倒角方块、炮台、阴影和世界坐标弹道。
- `src/app.js`：交互、菜单、存档和关卡流程。
- `npm ci` 安装锁定的官方 npm 依赖；`npm run build`：将源模块打成支持本地直接打开的 `game.js`。
- `npm test`：引擎与静态回归测试。
- `npm run serve`：可选本地 HTTP 服务。
- `qa/viewport.html`：实际游戏同源 iframe 尺寸与交互回归页面。`?w=320&h=568&auto=1` 可自动运行。

测试路由 `?qa=1` 使用独立内存状态，不读写正常玩家存档。没有统计、广告、跟踪、外部脚本或网络游戏请求。

## 2.0 视角修正

片头绿墙估测采用约 14° 侧向方位、46° 仰角的前左相机；菜单中的斜侧视角约为 32°/32°，对应混剪后半段。视频没有相机参数，以上是依据画面轴线估计，不是原作的精确设置。固定正交相机符合近似平行的画面边线，也不排除原作使用长焦透视。

新版包含真正的 3D 场景、光照、阴影、实例化体素，以及共用世界空间的炮台、炮口和炮弹。首关采用片头式的宽屋顶、8 层墙面，后续包含 14–16 层高的原创墙体。旧版中途存档原样恢复；尚未开打的旧关自动升级，重开或下一关使用新版几何。十二关的解锁与历史成绩保留。

设备像素比限制为 1.5，方块按颜色使用 thin instances；失去 WebGL 上下文时暂停并保留进度。具体设备帧率仍取决于 GPU，不把云浏览器测试当成真机认证。

Babylon 和 shader 全部打进本地 `game.js`，运行时不访问 CDN。依赖来源、锁定版本和许可见 `THIRD_PARTY_NOTICES.md`；许可证保存在 `vendor/`。

技术依据：[相机](https://doc.babylonjs.com/features/featuresDeepDive/cameras/camera_introduction)、[thin instances](https://doc.babylonjs.com/features/featuresDeepDive/mesh/copies/thinInstances)、[阴影](https://doc.babylonjs.com/features/featuresDeepDive/lights/shadows)。

## 2.0.1 渲染热修复

修复了 2.0.0 中四色体素批次意外共享实例矩阵缓冲的问题：画面可能只剩墨蓝色块，形状也缺失。每个颜色批次现在先分离 geometry，再设置 thin-instance 数据；消除后的动态上传和关卡恢复也有独立绑定回归检查。

同时将环境光/方向光强度从 0.85/1.15 改为 0.65/0.35，避免杏色地面红绿通道被过曝截断成亮黄色。未改颜色空间、相机、关卡数据或存档格式。新旧存档和当前进度保留。

静态模型和实际 Babylon 缓冲绑定测试通过不等于手机像素验收。云浏览器的 WebGL 仍受环境限制，最终手机画面需在启用 WebGL 的设备上核对。请使用带 `?v=2.0.1` 的地址；菜单底部显示渲染版本。
