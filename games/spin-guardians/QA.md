两组完整过程中合计 **121次**自动存档恢复，包含战斗中场和节点，序列化状态逐字节一致。六组最高同时敌人21、效果82、英雄12，均低于硬上限。生成敌人1753名，分裂与首领召唤使最终击杀数约1993–2009。

机器执行整局仅消耗约2.6–10.2秒墙钟时间，模拟累积的43–47分钟来自60Hz逻辑推进；这不是在手机上连续游玩一小时，也不是手机性能测试。完整逐波记录在 `tests/balance-results.json`。

方法：固定60Hz引擎，机器人仅调用普通招募、合成、晋升、天赋、组合装备、主动技能、奖励、事件和商店API。完整通关测试没有注入金币、生命、伤害或跳过波次；另外的单元测试使用人工场景只验证机制，不用于声称通关或时长。

战斗计时只计算引擎战斗推进，不含菜单、暂停、真人阅读、布阵与思考。额外8–15分钟构筑时间是设计估计，并非真人计时。常规一倍速目标45–75分钟；二倍速和主动提前援军均可能显著缩短。自动策略不能代表全部玩家，也不能证明难度已获得广泛真人验证。

## 1.2 手机布局修复（2026-10-11）

已从实际手机截图定位：桌面 `.game-layout` 定义的双列 `grid-template-columns` 与 `align-items:start` 没有在手机规则中清除。较晚的手机规则重新启用 `display:grid`，于是战场和操作区仍被放进左右两列，标题换行重叠，战場无法填满分配的高度。

修复后手机规则显式使用单列、上下两行及 stretch，战场和操作区各自指定行列，保留安全区高度扣减。标题与底部状态增加窄屏收缩保护；画布继续按容器可用宽高取较小值，保持 9:11 比例。

- JavaScript 语法检查通过。
- 全部 30 项引擎测试通过。
- DOM/Canvas mock UI 冒烟通过，含部署、合成、弹窗、暂停、存档与画布比例。这不是浏览器视觉测试。
- 新的 CSS 级联回归在 320、390、410、430、760px 宽度下通过，并确认 761、1280px 桌面双列保留。将发布版本 `9031a45` 的实际旧样式传给同一测试，五组手机尺寸均按预期失败，准确指出双列继承和缺少行列定位。
- 下方早期版本的尺寸计算仅验证公式，未验证最终 CSS 级联，因此没有发现本次双列缺陷。不能把那组计算视为实际布局通过证据。
- `tests/mobile-preview.html` 以同源 iframe 加载正式入口，用真实浏览器 CSS 视口检查 320×568、390×844 等尺寸。发布后的实际浏览器结果另行记录，不以静态计算代替。
- 未改变引擎、关卡数值、存档格式或存档键。未发布用户截图。

物理触屏、设备性能、移动地址栏伸缩和真实刘海安全区仍需设备验证；浏览器强制深色模式可能覆盖网站的浅色声明。
